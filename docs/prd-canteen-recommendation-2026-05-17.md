## 1. 文档目的与范围

本 PRD **反向梳理**校园食堂智能推荐系统当前已有功能，并补充本轮（7 天）迭代新增的"真实第三方支付集成"与"微信小程序学生端"两个增量目标，作为后续架构设计（Phase 3）与故事拆分（Phase 4）的输入。

## 2. 业务目标与成功指标（摘自 Brief）

### 2.1 业务目标
1. **作品集化**：2026-05-23 前交付可在 10 分钟内 demo 完整主线（点餐 / 推荐 / 数据看板 / 支付沙箱 / 小程序）的版本。
2. **前端工程质量提升**（D2 完成）：Pinia 状态收口、`VITE_API_BASE` 替换硬编码、关键页面拆分大组件、ECharts 懒加载。
3. **可解释推荐 UX**：前端展示"为什么推荐这道菜"。
4. **数据分析模块演示化**：mock 数据集开关，任意时刻图表非空。
5. **多端 + 真实支付**：微信支付 / 支付宝沙箱主流程 + 微信小程序学生主流程。

### 2.2 成功指标
- 30 分钟内本地从零启动整套系统（含数据初始化）。
- 关键页面 LCP < 2.5s，零 console 错误 / 未处理 Promise 异常。
- 三条 5 分钟 demo 主线全部可演示。
- 后台 mock 数据下所有图表非空。
- 至少 3 个前端面试常考点（路由守卫 / 状态管理 / 图表 / 组件封装 / Axios 拦截）能在项目中找到对应实践。

## 4. 关键用户旅程

### 4.1 学生点餐主线（点餐闭环）
浏览首页 → 推荐 / 菜品列表 → 加购物车 → 创建订单 → **微信/支付宝沙箱支付** → SSE 实时状态推送（PENDING → PAID → PREPARING → READY → COMPLETED）→ 评价 → 自动发放积分 → 积分商城兑换券

### 4.2 推荐引擎使用旅程
首页 SmartRecommend → 选择策略（融合 / cf / content / context / popular）或健康目标 → 查看推荐结果 + **推荐理由** → 加购或查看菜品详情

### 4.3 管理员数据决策旅程
登录管理后台 → Dashboard 看板（营收/订单/品类趋势）→ 高级分析（评价 NLP / 词云 / 关联规则 / 用户分群 / 异常检测 / 对比分析）→ 导出 Excel

### 4.4 小程序点餐旅程（本轮新增）
微信小程序 → `wx.login` 静默登录 → 浏览菜品 / 推荐 → 加购 → 下单 → **小程序原生支付** → 轮询 / 长连接获取订单状态 → 评价 → 积分商城

## 5. Functional Requirements（FR）

> 共 28 条；优先级：M=Must / S=Should / C=Could。`✅` 标记表示当前代码已实现，本轮工作为打磨 + 验收；`🆕` 表示本轮新增。

### 5.1 用户与认证（FR-001 ~ FR-003）

#### FR-001：账号注册与登录 `M` `✅`
**描述**：支持学号 / 用户名 + 密码注册和登录；登录成功颁发 JWT，前端持久化到 `localStorage`。
**验收**：
- [ ] 注册成功返回用户对象（不含密码）
- [ ] 登录返回 `{ token, user }`，token 在 24h 内有效
- [ ] 密码使用 BCrypt 加密保存
- [ ] 登录失败统一返回 401 + 友好提示

#### FR-002：当前用户信息查询 `M` `✅`
**描述**：`GET /api/users/me` 通过 JWT 返回当前用户。
**验收**：未携带 token 返回 401；token 失效 401 并清除前端状态。

#### FR-003：三种角色 RBAC `M` `✅`
**描述**：STUDENT / WINDOW_MANAGER / ADMIN 角色控制接口与路由访问。
**验收**：
- [ ] 后端：`/api/admin/**`、写接口要求 ADMIN 或 WINDOW_MANAGER
- [ ] 前端：路由守卫按 `meta.requiresAdmin` 和 `meta.allowedRoles` 校验
- [ ] Pinia `isAdmin()` 与守卫角色集合保持一致（修复历史不一致）

### 5.2 菜品 / 食堂 / 窗口（FR-004 ~ FR-006）

#### FR-004：菜品浏览与搜索 `M` `✅`
**描述**：菜品 CRUD、分类筛选、关键词搜索、按价格/评分排序、热销 Top N、促销筛选。
**验收**：
- [ ] 列表分页加载、无数据时占位
- [ ] 搜索支持中文关键词
- [ ] 价格升序、评分降序、销量降序三种排序

#### FR-005：食堂与窗口结构 `M` `✅`
**描述**：食堂 → 窗口 → 菜品三级结构；窗口可启用 / 停用。
**验收**：菜品挂在窗口下；窗口停用时菜品在用户端隐藏。

#### FR-006：菜品分类、套餐与促销 `S` `✅`
**描述**：菜品分类管理、套餐（含促销绑定）、促销活动配置与计算。
**验收**：促销价 = 原价 × 折扣或减免；价格字段统一 `BigDecimal`（`Combo.price` 历史 `double` 需迁移，列入本轮加分项）。

### 5.3 购物车与订单（FR-007 ~ FR-010）

#### FR-007：购物车增删改查 `M` `✅`
**描述**：登录用户购物车后端持久化；前端 localStorage 作为缓存。
**验收**：
- [ ] 改数量后实时更新小计、合计
- [ ] 清空购物车确认弹窗

#### FR-008：下单与取消 `M` `✅`
**描述**：从购物车下单，支持立即取餐 / 预约取餐两种 `PickupType`。
**验收**：下单创建订单 `PENDING` 状态；可在 `PENDING/PAID` 状态取消。

#### FR-009：订单状态流转 `M` `✅`
**描述**：`PENDING → PAID → PREPARING → READY → COMPLETED`，可 `CANCELLED`。窗口管理员触发 `prepare / ready / confirm-pickup`。
**验收**：状态变更写入 `OrderStatusHistory`；非法转换返回 400。

#### FR-010：订单实时推送（SSE） `M` `✅`
**描述**：`GET /api/orders/events` 推送当前用户订单状态变更。
**验收**：状态变更 ≤ 2s 内前端收到；连接断开自动重连。

### 5.4 支付（FR-011 ~ FR-013）

#### FR-011：支付主流程（Web 端） `M` `🆕`
**描述**：订单创建后跳转支付，支持微信支付（沙箱）+ 支付宝（沙箱）二选一。
**验收**：
- [ ] 调用 `POST /api/payments/orders/{orderId}/create`，返回支付参数（二维码 / 跳转链接）
- [ ] 支付成功后异步回调 `POST /api/payments/callback`，订单变为 `PAID`，推送 SSE 状态
- [ ] 回调必须做签名校验，未通过返回 400 并记录日志

#### FR-012：Mock 支付兜底开关 `M` `🆕`
**描述**：通过配置项 `payment.mode=mock|sandbox` 切换；`mock` 模式直接成功并触发回调逻辑，便于演示与降级。
**验收**：切换开关无需重启即生效（或文档化重启步骤）；前端无需关心模式。

#### FR-013：支付状态查询 `S` `🆕`
**描述**：订单详情页可主动查询第三方支付状态，避免回调丢失。
**验收**：调用第三方查询接口，结果与本地订单一致；不一致以第三方为准并修正。

### 5.5 评价与积分（FR-014 ~ FR-016）

#### FR-014：订单评价 `M` `✅`
**描述**：已完成订单可评价（文字 + 最多 N 张图片 + 评分）；评价 multipart 上传。
**验收**：评价提交后异步发奖励积分（事件机制 `ReviewCreatedEvent`）；同订单不重复评价。

#### FR-015：管理员评价回复与警示 `S` `✅`
**描述**：管理员 / 窗口可对评价回复；负面评价自动标警示，可触发通知。
**验收**：警示评价在后台高亮；通知出现在管理员 `AdminNavBar` 30s 轮询计数中。

#### FR-016：积分流水与商城兑换 `M` `✅`
**描述**：积分余额、流水查询；积分兑换餐券（卡券）。
**验收**：兑换扣积分 + 生成卡券记录 + 后台审核（`AdminVoucherExchangeController`）。

### 5.6 推荐引擎（FR-017 ~ FR-020）

#### FR-017：多策略推荐 `M` `✅`
**描述**：4 种策略 cf / content / context / popular；可单独调用或融合调用。
**验收**：`GET /api/recommendations/strategy/{type}` 返回不同结果；融合结果 `/personalized` 综合至少 2 种策略。

#### FR-018：推荐理由 `M` `✅`（前端 UI 本轮加强）
**描述**：`GET /api/recommendations/personalized/reasons` 返回每个菜品的推荐理由。
**验收**：
- [ ] 前端 SmartRecommend 组件每张菜品卡片显示理由 chip（如 "和你相似的同学常点 / 与你的口味偏好匹配 / 雨天适合喝热汤"）
- [ ] 理由文案为中文、≤ 20 字、可读

#### FR-019：健康目标推荐 `M` `✅`
**描述**：四种目标 `HIGH_PROTEIN / LOW_FAT / CONTROL_CARBS / CONTROL_CALORIES`，基于过去 7 天 `OrderItem` 能量与三大供能比评分。
**验收**：每个目标返回 Top N 菜品；用户下单后缓存脏标记，再次查询重新计算。

#### FR-020：今日新品 / 个性化热门 / 发现频道 `S` `✅`
**描述**：`today-new / today-personalized-hot / discovery` 三个延伸接口。
**验收**：首页轮播或卡片位呈现，UI 呼应。

### 5.7 数据分析与统计（FR-021 ~ FR-023）

#### FR-021：管理员数据看板 `M` `✅`
**描述**：`dashboard-summary / metrics`、营收趋势 / 订单趋势 / 品类趋势 / 排行榜。
**验收**：ECharts 渲染；时间范围切换 7/30/90 天；空数据走 mock 模式。

#### FR-022：高级数据分析 `M` `✅`
**描述**：评价 NLP（词云 / 关键词 / 菜品特征）、关联规则、用户分群、活跃时段、异常检测、对比分析、库存预警。
**验收**：每个分析子组件在 `AdvancedAnalysis.vue` 下挂载并能独立打开；图表可解释。

#### FR-023：Excel 导出 `S` `✅`
**描述**：菜品 / 订单 / 评价 / 用户四类数据 EasyExcel 导出。
**验收**：导出文件可在 Excel/WPS 打开，列头为中文。

### 5.8 通知与公告（FR-024 ~ FR-025）

#### FR-024：用户通知 `S` `✅`
**描述**：用户消息（订单变更、警示、积分发放等）；管理员警示通知。
**验收**：未读数 30s 轮询；点击标记已读。

#### FR-025：系统公告 `S` `✅`
**描述**：公开读 `/api/announcements`、后台写 `/api/admin/announcements`。
**验收**：首页 / 小程序显示置顶公告。

### 5.9 微信小程序（FR-026 ~ FR-028 · 本轮新增）

#### FR-026：小程序登录与鉴权 `M` `🆕`
**描述**：使用 `wx.login` 获取 `code`，后端用 `code2session` 换取 `openid`；首次自动注册学生账号，颁发 JWT。
**验收**：
- [ ] 用户授权后可直接进入主页面，无需手动输入账号
- [ ] 后续请求统一在 header 携带 `Authorization: Bearer <token>`

#### FR-027：小程序学生主流程 `M` `🆕`
**描述**：覆盖浏览 → 加购 → 下单 → 支付 → 订单状态 → 评价 → 积分商城。
**验收**：
- [ ] 学生主流程页面齐全：首页 / 菜品列表 / 详情 / 购物车 / 订单 / 订单详情 / 评价 / 个人中心 / 积分商城
- [ ] 与 Web 端共用后端 API
- [ ] 订单状态使用**短轮询（每 5s）** 替代 SSE（小程序不原生支持 SSE）

#### FR-028：小程序支付 `M` `🆕`
**描述**：调用 `wx.requestPayment` 拉起微信支付。
**验收**：沙箱环境下可走完整支付流程；失败 / 取消有明确提示。

## 6. Non-Functional Requirements（NFR）

### NFR-001：性能 - 接口响应时间 `M`
**描述**：在演示数据规模（< 10k 订单）下，95% 的非聚合接口 < 200ms，聚合统计接口 < 1s。
**验收**：Spring Actuator 或本地压测脚本验证。
**理由**：面试演示流畅度依赖。

### NFR-002：性能 - 前端首屏与关键交互 `M`
**描述**：登录后首页 LCP < 2.5s，菜品列表交互响应 < 100ms（输入即时反馈）。
**验收**：Chrome DevTools Performance 抽样。
**理由**：直接影响面试官第一印象。

### NFR-003：安全 - 鉴权与密码 `M`
**描述**：所有写接口与 `/api/admin/**` 必须 JWT + 角色校验；密码 BCrypt；JWT secret 通过环境变量覆盖。
**验收**：未携带 token 写接口返回 401；secret 默认值仅开发使用。
**理由**：基础合规与面试安全题加分。

### NFR-004：安全 - 支付回调签名校验 `M` `🆕`
**描述**：微信 / 支付宝回调必须验签；不符合返回 400 + 日志；重复回调幂等。
**验收**：篡改 body 验签失败；同一通知重复 10 次仅生效一次。
**理由**：真实支付场景下的必备防御。

### NFR-005：可扩展性 - 推荐策略可插拔 `S` `✅`
**描述**：通过 `RecommendationStrategy` 接口 + 策略模式，新增策略无需修改 `RecommendationServiceImpl`。
**验收**：新增策略实现类并标注 `@Component` 后自动生效。

### NFR-006：可用性 - 演示模式开关 `M`
**描述**：管理后台 / 数据分析模块在数据稀疏时可切到 mock 数据集，保证图表非空。
**验收**：URL 参数或 store 开关 `?demo=1` 即时切换。
**理由**：作品集"任意时刻可演示"的核心保障。

### NFR-007：可维护性 - 前端工程基础 `M`
**描述**：
- 所有 HTTP 调用走 `vue/src/api/` 资源模块（禁止组件内 `new axios`）
- `baseURL` 通过 `import.meta.env.VITE_API_BASE` 注入
- 状态优先 Pinia，剔除 localStorage 双写
- 大组件按职责拆分到 `components/`

**验收**：
- [ ] grep 全工程无组件内直接 `axios.create`
- [ ] `.env.development` / `.env.production` 覆盖 `VITE_API_BASE`
- [ ] `stores/user.js` 涵盖 token / user / role 三项；组件不再读 localStorage

#### NFR-008：可维护性 - 后端规范 `S`
**描述**：业务异常一律 `BusinessException`；当前用户取 `SecurityUtils.requireCurrentUserId()`；金额 `BigDecimal`。
**验收**：grep 无直接 `throw new RuntimeException`；新代码无 `double` 金额。

### NFR-009：兼容性 - 多端协同 `M` `🆕`
**描述**：Web 与小程序共用同一后端；后端不依赖 Cookie/Session，统一 JWT Header；CORS 配置允许小程序域名（开发可直连 `localhost:8089` 域名白名单）。
**验收**：
- [ ] 小程序 `wx.request` 在 `request:legalDomain` 配置中包含后端域名
- [ ] 跨端登录态互不污染（不同设备独立 token）

### NFR-010：可靠性 - SSE 与轮询降级 `S`
**描述**：Web 端 SSE 断开自动重连；小程序使用 5s 短轮询，且仅在订单详情页生效以节省请求。
**验收**：网络中断 5s 内恢复 SSE；小程序离开订单详情停止轮询。

### NFR-011：可观测性 - 日志与错误兜底 `S`
**描述**：全局 `GlobalExceptionHandler` 统一返回 `{message, code, status}`；支付 / 推荐关键路径有日志；前端 Axios 拦截器对 401/403/404/500 有友好提示。
**验收**：手动触发各种错误，前端弹出对应文案。

### NFR-012：可演示性 - 本地从零启动 `M`
**描述**：30 分钟内任何评审者可在本地启动完整系统（含数据库初始化、Redis、前端、小程序模拟器）。
**验收**：README 步骤 + docker-compose 或 SQL 脚本验证通过。

## 11. 假设

- 微信支付沙箱与支付宝沙箱在 D3 当天可联调（如商户号申请未通过，使用 Mock 兜底）。

## 13. 开放问题（Open Questions）

1. **支付双沙箱 vs 单沙箱**：D3 时间窗内是否优先做完一种（建议先微信支付）？
2. **小程序登录是否需要**手机号授权 / 实名校验？建议本轮仅做静默登录。
