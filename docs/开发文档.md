## 1. 项目概述

本系统是面向高校食堂场景的**点餐 + 智能推荐 + 数据分析**一体化平台，主要业务能力：

- 学生：浏览菜品、加购物车、下单支付、订单跟踪、评价、积分兑换券、个性化推荐
- 窗口管理员：管理本窗口菜品/订单/促销/评价回复
- 系统管理员：用户、食堂、窗口、菜品、订单、评价、积分商城、公告、数据分析全方位管理

工程目录：

```
canteen_recommendation_3.0/
├── canteen_recommendation.sql   # 数据库脚本（含初始数据）
├── java/                        # Spring Boot 后端
└── vue/                         # Vue 3 前端
```

## 3. 环境搭建与启动

### 3.1 前置条件
- JDK 17、Maven 3.9+
- Node.js 18+ / pnpm 或 npm
- MySQL 8.0+
- Redis 6.0+（本机 `127.0.0.1:6379`）

### 3.2 数据库初始化
1. 创建库：`CREATE DATABASE canteen_recommendation DEFAULT CHARSET utf8mb4;`
2. 导入 [canteen_recommendation.sql](../canteen_recommendation.sql)（含全部表结构与示例数据）。
3. Hibernate 会以 `ddl-auto=update` 自动同步实体结构变化，不会删除字段。
### 3.3 后端启动
配置 [application.yml](../java/src/main/resources/application.yml)（可通过环境变量覆盖）：

| 变量 | 默认 | 说明 |
|---|---|---|
| `DB_URL` | `jdbc:mysql://localhost:3306/canteen_recommendation` | MySQL 地址 |
| `DB_USERNAME` / `DB_PASSWORD` | `root` / `123456` | 数据库账号 |
| `FILE_UPLOAD_DIR` | `${user.dir}/uploads` | 图片上传目录 |
| `jwt.secret` | 内置默认 | 生产必须改 |
| `jwt.expiration` | 86400000 | Token 过期时间（毫秒） |

启动：

```bash
cd java
mvn spring-boot:run
```

默认监听 `http://localhost:8089`。

### 3.4 前端启动

```bash
cd vue
npm install
npm run dev
```

开发服务器：`http://localhost:3000`。
[vite.config.js](../vue/vite.config.js) 已将 `/api` 与 `/uploads` 代理至 `http://127.0.0.1:8089`；同时 [api/index.js](../vue/src/api/index.js) 中 axios 的 `baseURL` 硬编码为 `http://localhost:8089`，部署时需要同步修改。

## 4. 系统架构

```
┌─────────────────────────┐         ┌──────────────────────────┐
│   Vue 3 + Element Plus  │ ◀─JSON─▶│  Spring Boot 3 REST API  │
│   (Pinia / vue-router)  │         │  Spring Security + JWT   │
└──────────┬──────────────┘         └────┬─────────────┬───────┘
           │                              │             │
           │                       JPA/Hibernate   Spring Cache
           │                              │             │
           ▼                              ▼             ▼
       浏览器 localStorage             MySQL 8        Redis 6
       （token / cart / user）        （业务数据）   （推荐/统计缓存）
```

- 前后端完全分离，全部走 RESTful + JWT。
- 后端无状态：每次请求通过 `Authorization: Bearer <token>` 鉴权。
- 推荐结果、健康目标分析等重计算结果走 Redis 缓存 + 脏标记策略。
- 订单状态变更通过 **SSE (Server-Sent Events)** 实时推送。
- 文件（菜品图、评价图）落地到 `FILE_UPLOAD_DIR`，对外路径 `/uploads/**`。

### 5.3 鉴权与权限

- **角色**：`STUDENT`、`WINDOW_MANAGER`、`ADMIN`（枚举 `UserRole`）。
- **登录**：[UserController#login](../java/src/main/java/com/school/canteen/controller/UserController.java) → 颁发 JWT，前端写入 `localStorage`。
- **过滤器**：每次请求由 `JwtAuthenticationFilter` 解析；公开接口即使携带 token 也会被认证，便于做个性化展示。
- **白名单**：`POST /api/users/login`、`/register`、GET `/api/dishes/**`、`/api/recommendations/**`、`/api/windows/**`、`/api/promotions/**`、`/api/combos/**`、`/api/canteens/**`、`/api/weather/**`、`/api/announcements`、`/api/payments/callback`、`/uploads/**` 等。
- **写权限**：`/api/dishes/**`、`/api/windows/**`、`/api/promotions/**`、`/api/canteens/**`、`/api/combos/**` 的写操作以及 `/api/admin/**` 都要求 `ADMIN` 或 `WINDOW_MANAGER`。
- **密码**：BCrypt 加密保存。
- 业务代码统一通过 [SecurityUtils.java](../java/src/main/java/com/school/canteen/util/SecurityUtils.java) 的 `requireCurrentUserId()` 拿当前用户。

### 5.4 异常处理与响应

- 业务异常 [BusinessException.java](../java/src/main/java/com/school/canteen/exception/BusinessException.java) 携带 HTTP status 与 code。
- [GlobalExceptionHandler.java](../java/src/main/java/com/school/canteen/exception/GlobalExceptionHandler.java) 以 `@ControllerAdvice` 兜底，统一返回 `{message, code, status, details?}`。

### 5.7 推荐引擎（策略模式）

接口 [RecommendationStrategy.java](../java/src/main/java/com/school/canteen/service/strategy/RecommendationStrategy.java) 仅两个方法：`recommend(userId, limit)` 与 `getStrategyType()`。
四个实现在 `service/strategy/impl/`：

| 策略 | 主要思路 | 关键依赖 |
|---|---|---|
| [CollaborativeFilteringStrategy](../java/src/main/java/com/school/canteen/service/strategy/impl/CollaborativeFilteringStrategy.java) | 基于评价矩阵的用户协同过滤；结果缓存于 Redis `rec:cf:user:{id}` | Review 历史 |
| [ContentBasedStrategy](../java/src/main/java/com/school/canteen/service/strategy/impl/ContentBasedStrategy.java) | 结合 User 口味偏好、UserProfile、历史订单为菜品打分 | Dish.tasteTags |
| [ContextAwareStrategy](../java/src/main/java/com/school/canteen/service/strategy/impl/ContextAwareStrategy.java) | 引入时间、季节、天气、温度等上下文因子 | WeatherService |
| [PopularityStrategy](../java/src/main/java/com/school/canteen/service/strategy/impl/PopularityStrategy.java) | 销量 × 评分 | OrderItem 聚合 |

[RecommendationServiceImpl](../java/src/main/java/com/school/canteen/service/impl/RecommendationServiceImpl.java) 注入 `List<RecommendationStrategy>` 后按 `strategyType` 索引，对外暴露：

- `GET /api/recommendations/personalized` — 多策略融合
- `GET /api/recommendations/personalized/reasons` — 带推荐理由
- `GET /api/recommendations/strategy/{type}` — 指定策略，`type ∈ {cf, content, context, popular}`
- `GET /api/recommendations/health` — 健康目标推荐（走 [HealthGoalRecommendationService](../java/src/main/java/com/school/canteen/service/HealthGoalRecommendationService.java)）
- `GET /api/recommendations/health-goals` — 可选目标枚举
- `GET /api/recommendations/discovery` — 发现频道
- `GET /api/recommendations/today-new` / `today-personalized-hot` — 今日新品 / 个性化热门

健康目标计算基于过去 7 天 `OrderItem` 的能量与三大供能比，再针对 `HIGH_PROTEIN / LOW_FAT / CONTROL_CARBS / CONTROL_CALORIES` 评分，结果缓存于 Redis `rec:healthgoals:user:{id}`，订单变更时打"脏"标记。

### 6.2 路由与权限

定义在 [router/index.js](../vue/src/router/index.js)，所有页面 `() => import()` 懒加载。`router.beforeEach` 守卫的三层防线：

1. **登录态**：`meta.requiresAuth` + 无 `token` → 跳 `/login`。
2. **管理员域**：`meta.requiresAdmin` → 必须 `ADMIN` 或 `WINDOW_MANAGER`。
3. **精细角色**：沿 `to.matched` 逆序找最近的 `meta.allowedRoles`，未匹配则提示并跳回 `/home`。

主要路由：

| 路径 | 组件 | 限制 |
|---|---|---|
| `/login` `/register` | Login/Register | 公开 |
| `/home` `/dishes` `/cart` `/orders` `/profile` `/exchange` | 用户主流程 | 登录 |
| `/admin/dashboard` | [Dashboard.vue](../vue/src/views/admin/Dashboard.vue) | ADMIN / WINDOW_MANAGER |
| `/admin/analysis` | [AdvancedAnalysis.vue](../vue/src/views/admin/AdvancedAnalysis.vue) | 仅 ADMIN |
| `/admin/dishes` `/orders` `/reviews` `/promotions` `/windows` | 经营管理 | ADMIN / WINDOW_MANAGER |
| `/admin/users` `/announcements` `/vouchers` `/voucher-exchanges` `/canteens` | 系统级管理 | 仅 ADMIN |

### 6.3 状态管理

只有一个 Pinia store：[stores/user.js](../vue/src/stores/user.js)，提供 `login / logout / checkLoginStatus / updateUserInfo / getUserRole / isAdmin`。

> 当前实现中，多数页面直接读 `localStorage` 而非 store。购物车（key `cart`）也使用 `localStorage`。后续如要做多端同步，建议统一收口到 store。

### 6.4 HTTP 层

[api/index.js](../vue/src/api/index.js) 创建全局 axios 实例：

- `baseURL: "http://localhost:8089"`（生产部署需替换）
- `timeout: 15000`、`withCredentials: true`
- **请求拦截**：注入 `Authorization`，GET 请求附加 `_t=Date.now()` 防缓存，`FormData` 时去除 `Content-Type` 让浏览器写 boundary。
- **响应拦截**：按状态分流；401 清 token + 跳 `/login`，403 提示无权限，404 / 500 兜底文案。

## 8. 开发规范

### 8.1 后端
- 命名：Controller → `XxxController`，接口 → `XxxService`，实现 → `XxxServiceImpl`，仓库 → `XxxRepository`。
- 业务异常一律抛 `BusinessException(HttpStatus, code, message)`，禁止直接 `throw new RuntimeException`。
- 当前用户 ID 通过 `SecurityUtils.requireCurrentUserId()` 获取，禁止从入参中接收。
- 涉及金额字段使用 `BigDecimal`，禁止 `double`/`float`（历史 `Combo.price` 仍是 `double`，迁移时再补）。
- 推荐相关重计算必须走 Redis 缓存与脏标记；不要在控制器中直接遍历评价/订单。
- 新增表必须考虑 `ddl-auto=update` 不会删字段：删除字段时务必手动 DDL 并同步 SQL 脚本。

### 8.2 前端
- 新页面优先复用 Element Plus 组件库；统一中文 `zh-cn` locale。
- 所有 HTTP 请求走 [api/](../vue/src/api/) 模块，禁止在组件中直接 `new axios`。
- 新接口请补充对应 `api/*.js` 资源文件；命名使用 `xxxApi`。
- 路由必须设置 `meta.requiresAuth`、`meta.requiresAdmin`、`meta.allowedRoles`，新增后台菜单同步更新 `AdminNavBar.vue`。
- 状态优先放 Pinia store；仅本地 UI 状态用 `ref/reactive`。
- 大尺寸组件按业务拆到 [components/](../vue/src/components/) 下对应目录，禁止把可复用图表逻辑塞进页面。

### 8.3 Git
- 主分支 `main`，特性分支 `feature/*`，修复 `fix/*`。
- 提交格式建议：`<scope>: <动词原形> <内容>`，如 `dish: 修复促销价空指针`。
- 涉及表结构变更 → 同时更新 [canteen_recommendation.sql](../canteen_recommendation.sql)。

## 9. 部署

### 9.1 后端
```bash
cd java
mvn -DskipTests clean package
java -jar target/canteen-recommendation-1.0.0.jar \
  --DB_URL=jdbc:mysql://prod-db:3306/canteen_recommendation \
  --DB_USERNAME=xxx --DB_PASSWORD=xxx \
  --jwt.secret=<32+ chars> \
  --FILE_UPLOAD_DIR=/data/canteen/uploads
```
确保 Redis 与 MySQL 可达；`/uploads` 反向代理到该目录或直接由后端服务托管。

### 9.2 前端
1. 修改 [api/index.js](../vue/src/api/index.js) 的 `baseURL` 或改为读取 `import.meta.env.VITE_API_BASE`。
2. 执行 `npm run build`，产物在 `vue/dist/`。
3. 用 Nginx 托管 `dist/`，将 `/api`、`/uploads` 反代至后端。

Nginx 示例：

```nginx
server {
  listen 80;
  root /var/www/canteen;
  index index.html;

  location / { try_files $uri $uri/ /index.html; }
  location /api/      { proxy_pass http://backend:8089; }
  location /uploads/  { proxy_pass http://backend:8089; }
}
```

## 10. 关键风险与待办

1. **`baseURL` 硬编码**：前端生产环境必须替换为后端真实地址，建议引入 `VITE_API_BASE` 环境变量。
2. **JWT secret**：`application.yml` 默认值仅用于开发，生产环境必须通过环境变量覆盖。
3. **`Combo.price` 仍为 `double`**：建议迁移为 `BigDecimal`。
4. **Pinia 与 localStorage 双写**：当前部分组件直接读 storage，后续应统一收口。
5. **`isAdmin()` 与路由守卫角色集合不一致**：Pinia store 仅认 `ADMIN`，守卫认 `ADMIN/WINDOW_MANAGER`，需要在 store 中扩展。
6. **`ddl-auto=update`**：投产前建议改为 `validate` 并通过 Flyway/Liquibase 管理迁移。
